# Formal Feature Manifests — T07–T12

> Status: Hardened contract draft for experiment revision 1.
>
> These tasks are feature additions. The treatment base is not mutated unless a later validation shows the capability already exists.

## Shared rule

For a feature task to become admissible, the hidden oracle must fail against the unmodified treatment start because the requested observable capability is absent.

---

## T07 — Expose transport reconnect attempts

### Contract

`SessionRuntimeSnapshot` must expose:

```ts
transportReconnectAttempts: number
```

Semantics:

- reflects the current P2P `WebSocketService.reconnectAttempts`;
- is `0` when no P2P transport exists;
- is distinct from existing attach-level `reconnectCount`;
- snapshot subscribers are notified when the transport reconnect attempt count changes.

### Starting-state evidence

The frozen runtime snapshot contains `reconnectCount` from `AttachStateMachine`, but does not expose `WebSocketService.reconnectAttempts`.

### Hidden oracle

Drive one socket-loss retry and assert:

```text
attach reconnectCount remains its own value
transportReconnectAttempts == 1
```

Then establish the connection and assert the transport count returns to `0` after the transport's successful establishment semantics.

## T08 — Expose the last recovery cause

### Contract

`SessionRuntimeSnapshot` must expose:

```ts
lastRecoveryCause:
  | 'socket-loss'
  | 'attach-timeout'
  | 'visibility-wake'
  | null
```

Semantics:

- `socket-loss` when recovery begins from a live transport loss;
- `attach-timeout` when an attach request exhausts its request timeout and enters retry recovery;
- `visibility-wake` when the explicit browser wake path initiates a stopped-transport reconnect;
- resets to `null` after a stable successful attach.

Implementation is not prescribed. The cause may flow through a transport event, runtime event, or another typed internal signal.

### Starting-state evidence

The frozen snapshot has phase/count/connection state but no typed recovery-cause field.

### Hidden oracle

Exercise the three trigger classes independently and verify the snapshot cause; then complete a current-generation attach and verify it clears.

## T09 — Add structured visibility-wake telemetry

### Contract

The wake-reconnect hook must expose one structured callback surface:

```ts
onReconnectRequested?: (event: {
  reason: 'visibility-wake';
}) => void
```

The exact containing options object is implementation-defined; the observable callback semantics are fixed.

Semantics:

- emit exactly once when visibility wake actually calls `connect()`;
- emit zero times when the wake path is skipped because the service is null, unauthenticated, not visible, not disconnected, or disposed;
- callback observation must not itself change reconnect behavior.

### Starting-state evidence

The frozen hook logs to the console but has no structured observer/callback surface.

### Hidden oracle

Drive visible/disconnected/live and every skip guard; count structured callback emissions independently from `connect()` calls.

## T10 — Configurable attach retry budget

### Contract

`SessionRuntimeConfig` must accept:

```ts
attachRetryLimit?: number
```

Default behavior remains equivalent to the frozen `P2P_MAX_RECONNECT` value.

Semantics:

- a per-runtime value controls attach-timeout retry exhaustion;
- manual-route exhaustion still ends failed;
- automatic-route exhaustion still converges to relay;
- two runtime instances may use different budgets without global mutation.

### Starting-state evidence

The frozen attach state machine uses the module-level `P2P_MAX_RECONNECT = 10` constant.

### Hidden oracle

Create runtimes with retry limits `1` and `3`, drive attach timeouts, and prove their exhaustion points differ while a runtime with no option retains the default.

## T11 — Configurable attach timeout

### Contract

`SessionRuntimeConfig` must accept:

```ts
attachTimeoutMs?: number
```

Default behavior remains equivalent to the frozen `ATTACH_TIMEOUT_MS = 10_000`.

Semantics:

- the value is applied to every P2P `client.attach` attempt for that runtime;
- retry attempts preserve the configured timeout;
- two runtimes may use different timeout values independently.

### Starting-state evidence

The frozen `SessionAttachController` always sends the module-level `ATTACH_TIMEOUT_MS` constant.

### Hidden oracle

Use fake timers and runtimes with short distinct values; verify the outgoing attach options and retry timing use each runtime's configured value.

## T12 — Expose derived recovery mode

### Contract

`SessionRuntimeSnapshot` must expose:

```ts
recoveryMode:
  | 'none'
  | 'p2p-retry'
  | 'candidate-rotation'
  | 'forced-relay'
```

The mode must be derived from existing runtime/policy state rather than maintained as an independent duplicated state machine.

Semantics:

- `none` outside active recovery;
- `p2p-retry` while attach retry budget is driving repeated attach attempts;
- `candidate-rotation` while recovery has advanced away from the initial candidate and is still P2P;
- `forced-relay` once automatic recovery has switched the runtime to relay;
- successful stable attach returns the derived mode to `none` where applicable.

### Starting-state evidence

The frozen runtime exposes phase, active URL, reconnect count, forced-relay behavior, and candidate policy internally, but no unified recovery-mode projection.

### Hidden oracle

Drive each existing recovery path and assert the snapshot projection without requiring a second mutable recovery-state variable.
