# Formal Refactor / Evidence Manifests — T19–T24

> Status: Hardened design for experiment revision 1.

These tasks do not all use a runtime bug fixture. Refactor tasks use structural predicates plus behavior preservation. Verification tasks use hidden mutation testing so a meaningless test cannot satisfy the benchmark.

---

## T19 — Replace prose-string transport failure classification with a typed failure kind

### Starting-state evidence

`SessionAttachController` currently owns a `ReadonlySet<string>` containing transport error prose such as `Connection lost`, `WebSocketService disposed`, and `Connection timeout`.

Revision-1 acceptance fixes the false-result contract to:

```ts
type AttachFailureKind = 'timeout' | 'transport' | 'agent';
type AttachResult =
  | { ok: true }
  | { ok: false; kind: AttachFailureKind; error: string };
```

### Required result

The attach recovery boundary consumes a typed/discriminated failure kind rather than deciding transport-vs-agent semantics by matching error message strings.

Observable behavior must remain unchanged for:

- attach timeout;
- transport loss/disposal/connection failure;
- genuine agent error acknowledgment;
- contract-violating promise rejection.

### Structural acceptance

Hidden source analysis must confirm:

- the controller no longer contains a set/list of transport error prose used for classification;
- classification crosses the transport/feature boundary through a typed field or discriminated result;
- changing human-readable error text alone cannot change failure classification.

### Behavior acceptance

Existing controller/runtime failure tests remain green, with additional hidden cases that vary error prose while keeping the same typed failure kind.

## T20 — Make attach transition output one explicit typed action

### Starting-state evidence

`AttachTransitionResult` currently carries independent booleans:

```text
forceRelay
bumpRouteEpoch
retryAttach
```

Some combinations are nonsensical but representable.

### Required result

Represent recovery intent as one discriminated `action` value so conflicting actions are unrepresentable.

Revision-1 observable shape:

```ts
type AttachRecoveryAction =
  | { type: 'none' }
  | { type: 'retry-attach' }
  | { type: 'force-relay'; bumpRouteEpoch: true };

interface AttachTransitionResult {
  phase: AttachPhase;
  reconnectCount: number;
  action: AttachRecoveryAction;
}
```

The legacy independent `forceRelay`, `bumpRouteEpoch`, and `retryAttach` result fields must no longer be authoritative.

### Structural acceptance

Hidden analysis confirms transition consumers switch/narrow on one action discriminator rather than coordinating multiple independent recovery booleans.

### Behavior acceptance

All pre-existing state-machine, controller, and runtime tests pass without changing their intended external behavior.

## T21 — Separate transport generation from attach-attempt identity

### Starting-state evidence

The frozen slice uses plain `number` for both transport generation and controller attach-generation/epoch identity.

### Required result

The two identities become distinct nominal/opaque/branded types in the selected slice so they cannot be accidentally substituted without an explicit conversion/constructor.

Revision-1 exported type names are fixed for machine acceptance:

```ts
TransportGeneration
AttachAttemptGeneration
```

They must be distinct at the TypeScript type level.

### Structural acceptance

Hidden TypeScript/source checks confirm:

- `StartP2PAttachParams.transportGeneration` does not use an unqualified plain `number` identity;
- the controller's attach attempt/epoch identity uses a different type;
- direct accidental assignment between the two identity types is rejected by type checking or requires an explicit unwrap/conversion.

### Behavior acceptance

No runtime behavior change.

## T22 — Extract reconnect backoff into an independently testable policy

### Starting-state evidence

The frozen transport has a private `reconnectDelayMs` helper in the service module. The calculation is deterministic but has no independently owned policy/evidence surface.

### Required result

Backoff calculation becomes a separately owned pure policy under the reconnect capability.

Revision-1 acceptance requires the socket public surface to export:

```ts
computeReconnectDelayMs(attempt: number, baseDelay: number): number
```

The canonical implementation may live elsewhere (especially in Treatment C), but the compatibility/public socket surface must expose it.

Preserve:

```text
base delay
exponential growth
attempt indexing
30-second cap
```

### Structural acceptance

The WebSocket service consumes the policy rather than owning the formula inline/private.

### Evidence acceptance

Dedicated tests exercise at least:

- first attempt;
- several increasing attempts;
- custom base delay;
- cap behavior;
- deterministic repeated calls.

## T23 — Add an invariant test for competing recovery signals

### Starting-state evidence

The runtime has tests for ordinary single force-relay convergence, but not an explicit race-shaped invariant where force-relay decision competes with a stale/late recovery signal.

### Required evidence

Add a deterministic test proving:

```text
automatic recovery decides force relay
+ stale/late candidate or transport recovery signal
→ one force-relay runtime event
→ one relay begin
→ no return to P2P recovery
```

### Hidden mutation test

A test is not accepted merely because the clean suite passes.

Evaluation runs:

1. submitted test against clean implementation — must pass;
2. a hidden mutation that makes the force-relay transition non-idempotent under a competing signal;
3. the submitted test must fail against that mutation.

If the new test survives the mutation, T23 fails.

## T24 — Add an invariant test for full automatic recovery convergence

### Starting-state evidence

The frozen test suite covers transport loss, candidate advancement, attach retries, and relay fallback in separate tests, but does not prove the entire recovery chain in one scenario.

### Required evidence

One deterministic test must drive:

```text
attached P2P
→ transport loss
→ reconnect / candidate recovery
→ attach retry or candidate exhaustion
→ automatic forced relay
→ attached relay
```

and prove:

- no duplicate attach for one transport generation;
- no duplicate force-relay transition;
- final state converges to attached relay;
- stale P2P work cannot regain authority.

### Hidden mutation test

After the clean test passes, hidden evaluation mutates one convergence edge (for example suppressing candidate-exhaustion force-relay or allowing stale P2P work to reassert authority).

The submitted integrated test must kill the mutation.

---

## Research implication

Verification tasks are scored by **evidence strength**, not test-file existence.

```text
test exists
  ≠
test proves the invariant

test passes clean + fails known semantic mutation
  = stronger evidence
```

This mutation-based acceptance is part of the benchmark methodology and should be reported separately from ordinary coding-task success.
